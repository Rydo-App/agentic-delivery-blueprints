# Code of conduct

This code applies to everybody who takes part in this repository: the people who write
issues, the people who review changes, the people who merge them, and the agents that
work in it. An agent of the fleet is held to the same standard as a person, and the
standard is the same in both directions.

## The behaviour that is expected

- Be accurate. Say what you did, what you checked, and what the output was.
- Say plainly what you did not do and what is still unverified. An honest gap is worth
  more than a confident claim, and it is what makes the rest of the report trustworthy.
- Give a review of the change, not of the person who wrote it.
- Ask before you assume, and answer a question that is asked of you.
- Respect the work of others, including the work you would have written differently.
- Accept that a maintainer may say no to a change, and that this is not a judgement of
  the person who proposed it.
- Keep the repository usable for the next person: a change that leaves the tree in a
  state that nobody else can pick up is not finished.

## The behaviour that is not accepted

- Harassment, in public or in private, in an issue, a pull request, a review or a chat.
- Personal attacks, insults, and comments about a person's character, their employer or
  their level of experience.
- Sexualised language or imagery, and unwelcome sexual attention.
- Publishing somebody's private information, and publishing anything that identifies a
  real system, a real customer or a real person's address.
- Deliberately misleading another contributor, in a report, in a review or in a commit
  message.
- Publishing a credential, a token or a key, in a public issue, a pull request, a
  comment or a log, and publishing one deliberately.
- Taking work that somebody else has claimed, or rewriting the history that somebody
  else depends on.
- Sustained disruption of the work of others.

## How to report

Report a problem to the maintainers of the repository. Use the private channel when the
report is about a person, when it is about a security problem, or when a public report
would make things worse for whoever is named in it. The security route is described in
[SECURITY.md](SECURITY.md), and a report of a security problem is never filed as a
public issue.

A report is taken seriously. It is looked at, and the outcome is communicated to the
person who reported it.

## What happens next

1. The report is read, and the maintainer decides whether it describes a behaviour that
   is not acceptable here.
2. When it does, the people involved are told what was reported, in a way that says as
   little as possible about who reported it.
3. A response follows. It may be a warning, a request to change behaviour, a temporary
   removal from participation, or a permanent one. The response is chosen by what the
   behaviour needs, and not by what is easiest to carry out.
4. The maintainer who handled the report does not take part in handling any follow-up
   report against the same person.

The aim is to keep the repository a place where people and agents can work without
being harassed, and to warn the person concerned before they are removed.

## Attribution

Adapted from the Contributor Covenant, which is a widely used basis for a code of
conduct of this kind, with the parts about enforcement rewritten for a repository that
is worked on by agents as well as by people.

## For an agent of the fleet

An agent that drafts a message, an issue, a review or a commit message is the author of
that text, and this code applies to it in full.

- An agent does not decide for itself that a report is unwelcome because the report
  criticises a change the agent wrote. It reports it.
- An agent does not answer a question it was not asked, and it does not keep a
  conversation going that a person did not start.
- An agent does not publish anything that identifies a real system, and it does not
  paste a credential into a place that is not private.
- An agent reports a blocker with the same honesty as everything else: the symptom, the
  cause, how it was found, the fix, the guard and the lesson.
